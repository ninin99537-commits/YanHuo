# 烟火 · 世界运转系统 (Yanhuo)

每次更新项目同步更新此说明

一个运行在酒馆助手 (Tavern Helper) 中的脚本项目。与《彼方》互补且尺度分工明确: **彼方记录"小事件"——具体 NPC 的个人生活与行踪; 烟火只记"大事件"——势力、群体、地区、天时与远方变化**。主角看不见的地方, 时间照常流逝、各方按自己的盘算行动——世界不围着主角转, 主角只是世界里的普通一员。玩家通过面板以上帝视角看世界自转, 角色（主角）则只通过"传闻/告示/口信"等渠道自然听说这个世界。

## 工作原理

每次 AI 完成正文回复后 (频率可配), 用独立的 OpenAI 兼容 API 请求世界引擎。消息结构 (v1.4 起, 与彼方同款):

```
(头部填充开) user: 填充文本/内置小说原文     ← AI 收到的第一条
system: 核心提示词 (+防截断免责段)
user:   任务 (世界状态/最近剧情/正文/世界书)
(破限开) system: SPECIAL NOTE 身份强化       ← 任务后贴脸
(破限开) assistant: 承诺                    ← 看过任务后的应答
(预填充开) assistant: '{'                   ← 连续 assistant, JSON 起手
```

每次 AI 完成正文回复后 (频率可配):

```
正文生成完成 (防抖 800ms, 连发只推最后一条)
      ↓
烟火推进世界 (使用独立的 OpenAI 兼容 API)
      ↓
推进世界时间 / 事件因果演化 / 势力动向 (允许"无事发生")
      ↓
世界状态整体写入本次分析的楼层 (快照随楼层存亡)
      ↓
世界动向写入角色卡主世界书常驻条目, 主AI每回合都能读到
```

### 正文时间守卫

烟火的世界时钟以**最新一层正文**为唯一时间依据, 不会因为世界书里的未来日期或“世界自转”自行跳日:

- 正文写出明确的年月日时, 世界时间的日期必须与正文最新日期一致; 正文明确跨越数小时、数天或数月时, 允许直接跟随新日期。
- 正文只写“次日”“两周后”“几个月后”等相对跳跃时, 脚本按词义换算成允许的日期范围, 超出范围的模型结果会触发原有重试。
- 正文没有时间线索时, 世界时间日期必须沿用上一轮, 不允许凭空跨日; 时分等细节仍可由模型按剧情补全。
- 校验规则同时写入提示词与代码, 调试日志会记录本轮的“正文时间约束”, 便于确认一次推进为何被接受或拒绝。

因此, 一层正文确实经过几小时、几天、几个月并不会被代码拦截; 只有世界时间的跳跃没有正文依据, 或超出了正文明确给出的日期/范围, 才会被拦下。推荐把自动推进频率设为每 1~3 条 AI 回复, 让正文时间线索与世界快照保持足够近的上下文。

### 第一定律: 世界纯自转, 不围着主角转

- 每回合素材优先从五层常驻档案里长出来——**地域 / 大势 / 伏笔 / 节令 / 指标**——不依赖正文; 正文只用于推时间、更新主角所在地域、以及可选的世界级涟漪;
- 硬规则: 事件清单里大多数事件的当事人和地点都不在正文里; 禁止为主角编织巧合、钩子、机缘, 禁止让事件刻意针对或为难主角;
- **事件合格线**(三问全过才算): 集体/组织/制度/公共层面的动作或后果; 会被跨地区的人当作议题/情报; 对格局或某方处境有可累积的后果。天气/基础设施故障/市井日常/个人起居一律不入账;
- 势力暗中行动走**隐秘事件** (`隐秘`: 公开/隐秘): 不走公共渠道, 默认只进面板不注入主 AI (可开关注入并标注"主角绝不可能知道"); 隐秘可曝光 (事败/走漏/见报) 翻转为公开;
- 主角是否听说某件事, 由主 AI 按常识与剧情把握, 引擎不再维护主角知晓台账。

### 面板 (五页)

悬浮球 (46px 墨印, 可拖动, 位置记忆) 点击弹出小窗面板 (可拖动, 点外部不关闭, 仅关闭按钮或再点悬浮球可收起):

| 页面 | 内容 |
| ---- | ---- |
| **此刻** | 世界时间/氛围/大势、迫近警告 ("山雨欲来")、进行中事态与势力速览、推进/暂停自动/修笔(手动改概述)/清空 |
| **风闻** | 事件纪事流 (最新在前), 按阶段/规模筛选, 每条带时间/地点/规模/传播/知晓/渠道/势力/阶段/迫近/隐秘徽标与前情/可展开的演变时间线, 事件可编辑知晓与隐秘与前情 |
| **脉络** | 势力档案 Master-Detail: 目标/动向/前情/势力范围/对外关系/头面人物 |
| **日志** | 最近一次推进的完整请求/输出/报错 (可展开可复制)、注入给主AI的内容预览、控制台输出、一键「复制报错发给助手」 |
| **设置** | 接口配置 + 命名预设、运转设置、楼层标签过滤、世界书读取范围与排除 |

### 读世界书: 主AI读到什么, 烟火读到什么

世界推进时直接调用酒馆模板环境的 `getWorldInfoActivatedData`——**与主 AI 完全相同的激活逻辑** (蓝灯常驻、绿灯关键词扫最近正文), 主 AI 匹配不到的条目烟火也读不到。条目里的 ACU 模板 (`<if cell:...>`)、EJS 模板、酒馆宏都会按主 AI 的方式先求值再注入。默认只读角色卡主+附加世界书与聊天世界书; **全局世界书有开关** (默认关); 支持按条目名/关键词排除, 烟火与彼方自己写入的条目自动排除。

### 与彼方的分工

彼方管"人"(NPC 个人生活, 小事件), 烟火管"世界"(势力/地区/远方, 大事件), 两边各记各的、互不重复:

- 烟火推进时**不读取彼方数据**、也不生成人物层面的日常事件——人物归彼方, 世界归烟火;
- 读世界书与主 AI 完全一致: 彼方写入的 NPC 条目也照常读取(它们就是世界的一部分), 但提示词不提彼方, NPC 状态只作背景、不作事件素材;
- 主 AI 两份都读: 彼方的 NPC 状态 + 烟火的世界动向, 由主 AI 在剧情里自然融合。两插件彻底解耦, 彼方未安装时烟火照常运转。

## 配置

### 接口

- **独立接口**: 任何 OpenAI 兼容服务 (地址末尾自动补 `/v1`), 「获取模型列表」拉取后下拉选择, 「测试连接」发一条短消息验证;
- **命名预设**: 可保存多套接口配置 (地址/密钥/模型/参数整体保存), 一键加载切换, 不用重复填写;
- **流式 / 预填充 / 温度 / 最大输出Token**: 对接不同模型的兼容选项。

### 运转

- **自动推进 + 更新频率**: 每次或每 N 条 AI 回复推进一次; 正文过短 (疑似截断) 自动跳过;
- **注入世界动向到主AI**: 写入角色卡主世界书常驻条目「【烟火】世界动向」(蓝灯常开、禁递归), 切换聊天自动重写当前聊天的内容, 关闭或世界为空时删除条目; 注入内容为 世界总览 + 大势 + 地域 + 势力 + 公开事件, 条数与字数均不设上限;
- **注入隐秘事件到主AI**: 默认关闭——隐秘事件只进面板; 开启后以"主角绝不可能知道"的标注注入, 帮主 AI 写好暗中戏;
- **节令历法 / 世界指标**: 两个可选层开关, 关掉即不生成、不维护该层;
- **读取最近回复数 / 读取世界书 / 包含全局世界书 / 世界书排除** (世界书无条数与字数上限——主 AI 激活多少就读多少);
- **头部填充文本**: 可自定义的填充文本, 开启「头部填充」后作为**第一条消息**单独发送(与彼方同款), 留空使用内置小说原文;
- **楼层标签过滤**: 排除/只读 指定标签 (如 `thinking`、`aftertalk`), 兼容带属性写法, 始终清理 HTML 注释与 Subtext 思维链整块。

## 楼层快照: 删除楼层 = 世界自动回退

世界状态整体存在**楼层变量** (键 `烟火`) 里, 每次推进写入本次分析的最后一条楼层:

- **删除楼层**: 快照随楼层消亡, 世界自动回到更早楼层的快照 (保留最近 N 份, 份数可在设置「快照保留份数」调整, 1~100 默认 10; 写入新快照时物理清理超额);
- **回退窗口耗尽**: 连续删楼/编辑把全部快照锚点作废后, 世界会归零 (等同新开局)——想删更多楼还保住世界, 就调大保留份数; 注意每份快照几KB~30KB, 调得越大聊天文件越胖;
- **重roll/regenerate**: 新 swipe 页没有快照, 自动回到上一层状态, 随后正常推进;
- **编辑楼层**: 楼层内容 hash 与快照不一致时该快照作废 (继续往前回退);
- **切回旧 swipe 分支页**: 恢复该页当时的快照;
- **清空世界**: 记录「清空层」, 之后只推进比它更新的楼层, 不会从旧楼层重新长出旧事件。

聊天变量 (键 `烟火`) 只存轻量索引 (快照楼层列表 + 清空层)。**每个聊天都是独立的世界**——切换聊天/角色卡互不干扰, 新聊天从零建档。

## Debug

- 日志页记录每次推进的: 使用楼层、发送给世界引擎的完整内容、AI 输出、报错 (含脱敏接口信息与堆栈), 均可展开复制;
- 「复制报错内容发给助手」一键复制完整报错报告, 直接丢给 AI 助手排查;
- JSON 解析/结构失败自动重试 (最多 3 次, 原样重发同一份提示词), 推理模型只输出思维链时给出明确诊断;
- 控制台输出在面板内可见, 不用开浏览器控制台。

## 数据存储与去敏

- **设置**: 全局变量 (键 `烟火_settings`) —— 接口配置等敏感信息只存在酒馆服务器端, **导出脚本不会携带**; 局域网设备共享同一份;
- **世界状态**: 楼层变量 + 聊天变量 (见上), 严格按聊天隔离;
- **界面偏好**: 全局变量 (键 `烟火_界面`) —— 悬浮球位置/面板位置/主题。

## 安装

1. 运行 `pnpm build` (或 `pnpm watch` 开发) 生成 `dist/烟火_世界运转/index.js`;
2. 在酒馆助手中新建脚本, 内容填 `import 'http://localhost:5500/dist/烟火_世界运转/index.js'` (实时监听模式) 或直接粘贴打包产物, 启用即可;
3. 页面出现悬浮球, 点击进入面板, 在「设置」里配好接口后点「推进世界」建立世界档案。

无脚本按钮——所有手动操作都在面板里。

## 2026-10-01 — v2.3 两条通路各删一个开关 + 输出上限默认抬高

- **删掉「走酒馆服务器转发请求」开关**: 它以前是"接口不支持浏览器跨域(CORS)时才开"的选项, 关掉就走浏览器直连——同一件事两条路, 报错文案/超时/中断时机都不一样。现在**转发是唯一通路**(拉模型列表、发请求、中断全交给酒馆服务器), 设置里不再有这个开关; 老设置里残留的同名字段被忽略、不会报错, 日志页「复制报错」里那行 `服务端转发: 开/关` 也一并去掉, 随之消失的还有直连那条支路专属的报错(如"接口不支持流式响应(body 为空), 请关闭「流式」开关后重试");
- **删掉「关闭模型思维链」开关**: 请求固定按 OpenAI 兼容格式发出, 不再切换 source、不再附 `thinking: {type: disabled}`, 生成超时的报错文案同步去掉"可开启「关闭思维链」"这句指路(只留"调小「最大输出Token」后重试");
- **「最大输出Token」默认 2048 → 60000**: 没填过这项的新配置直接拿新默认 (老设置里已填的值不受影响); 输入框顺带去掉 `step="128"`——60000 不在 128 的步进格上, 点微调箭头会跳出怪数;
- **解析层两处静默错判**: ①键名别名归一化会给**任何**可解析对象凭空添一个值为 undefined 的「世界」键, 而载荷识别只看键名不看值——于是"优先挑世界推进载荷 / 都不像时取第一个 / 剥离切坏就降级到原文"三件事一起失效, 模型输出前面跟着伪 JSON 示例时可能挑错那一块; 现在只在原文本来就带该键时才改写(与其余六个区块同口径)。②剥离重复思考字段时, 全局正则的 `lastIndex` 没在重建字符串后归零, 会从旧位置继续扫、漏掉挪到更前面的思考字段(彼方那份一直有这一行, 烟火漏了);
- **内部整理**(对使用无感): 解析抢救层、五层字段表、编辑会话、世界状态落盘、面板机制与配色/几何常数各自独立成 module, 两家世界书求值器合成 `共用/条目求值.ts`(ACU 直连收进 host 接缝), 并各自补上用例。

## 2026-10-01 — v2.2 面板手改与 AI 同一套规矩

- **面板手改受同一套规矩管**: 五层档案与势力的容量上限、同名条目、空名称、事件标题重复——以前面板能存进去, 而下一轮 AI 推进时会把它裁掉或留下重名; 现在两条路走同一套规矩, 被拦下时面板会说明原因(「地域最多 8 条, 请先删掉一条再添加」这种), 编辑框保留你填的内容等你改;
- **事件编辑框不再凭空消失**: 以前它认的是"对象是不是同一份", AI 一推进整棵数据树就换了, 于是你正在改的事件会突然不见、输入全丢; 现在按事件 id 认;
- **日志页的改动账目按 id 认**: AI 给某件事改个名字, 日志不再报成"移除一条 + 新增一条", 而是记为一次推进;
- **改动设置立刻生效**: 设置读完的 500ms 缓存以前没有失效语义——刚关掉的开关在同一轮推进里还可能按旧值走; 现在写回即失效。另外全局设置读不到(被清空/读取报错)时会回退本机那份, 不再拿上一次的值充数(以前只有刷新页面才能恢复);
- **"世界有没有数据"只剩一份判据**: 只推了五层档案、还没长事件的世界, 不再被误判为空而删掉注入条目(启动补读改用同一份, 以前它只查「时间」与「事件」两项);
- **删楼后的重新对齐不再被吞掉**: 删楼后 2 秒内若来一条过短或隐藏的回复, 以前这次重新对齐会被取消并且再也不补, 面板会一直显示已删楼层的数据; 现在只有"真的推进成功了"才取消;
- **接口偶发截断会自动重推一次**: 有的接口会把长输出砍在半路(真机上遇到过一次: 3284 字的世界 JSON 被砍断, 同一个提示词手动重推就成功)。以前这种"整段不是 JSON"一律当场失败、要你自己再点一次; 现在识别出"有 `{` 没闭合"是接口侧截断, 就原样重推(最多三次里的正常次数), 而真正的"AI 只输出了文字"仍然当场失败, 不浪费次数;
- **快照没写进楼层时会说一声**: 楼层已被删除这类情况下, 以前照样弹"已保存"、刷新后改动消失; 现在明确提示改动没落盘。

## 2026-09-27 — v2.1 入账门槛与"纯带旧账合法化"

- **问题**: 事件清单越积越多, 现代都市世界观下"某街道管委会联合消防踏勘连廊避雨"这类**某栋楼/某项具体技术动作**被误判为要事入账。根因有三: ①事件合格线只问"集体层动作"没问"规模门槛", AI 把"政府出的动作"都当合格; ②"五层每层都要动一动"是 5 个强制动作点 vs 维护旧账只有 1 个步骤, 结构偏向"必须有产出"; ③伏笔机制本身是"埋→爆"的生产线, 到点必须兑现成事件。
- **世界观标尺**(提示词新增): 要事门槛按世界观取等价位——现代都市=市级/行业级; 赛博朋克=巨型企业部门级/城区级; 修仙=宗门内门级/坊市级; 古代=县级/商路级。**低于要事门槛的(某栋楼/某街道/某店铺/某项技术动作)一律不入账**, 并给现代都市的明确反例(管委会踏勘/避雨方案/社区调解/常规消防检查等)。
- **"纯带旧账"合法化**: 最高原则、Step 2/Step 3、任务指令三处同步加"该动的动、不该动的原样带回"、"若本轮五层都没实质推进, 事件清单原样带回, 一件新事件也不许新增——纯带旧账的回合合法且常见, 占所有回合的一半以上也正常"。消除"五层每层都要动一动"对 AI 的产出压力。
- **伏笔允许自然消亡**: 世界走向变了/剧情偏离/线头埋久了失去意义时, 直接从清单删除即可, 不必强行兑现成事件——堵住"伏笔到点必须兑现"的硬造事件通道。
- **历史限制段补完整状态声明**: "你输出的是完整 JSON 状态而不是补丁——所有未变化的字段都必须原样带回, 一个都不许漏", 减少 AI 漏带字段依赖脚本 inherit 兜底。
- **记忆回溯标注前置**: user 任务的世界书段头部同步加"<记忆回溯>…</记忆回溯> 是剧情历史概要不是世界设定, 不要复述、不要从中领取'必须推进的任务'"——避免 AI 把记忆插件内容当成世界设定或行动指令。
- **正文用途分级**: 任务指令 1 明确"时间必须从正文推(必做)、更新主角所在地域(必做)、正文大事的世界级后续(可选)", 消除"几乎不看正文"的误导(时间总得从正文读)。
- **代码兜底补漏**: ①「世界.氛围」AI 漏带时沿用旧值(与总览/势力字段同款), 不再被一次疏忽清空; ②inject.ts `hasWorld` 补五层档案判断——只推了五层还没长事件时不再误判"世界为空"误删注入条目; ③悬浮球界面 tab 类型补 'world'(TS 严格化); ④删除 v1.8 已不校验的 `楼层hash` 字段写入与 `hashString` 函数。
- **JSON 模板 id 注释**: 输出要求处补"旧事件填它原有的 id 原样带回, 全新事件留空 \"\" 由脚本签发, 严禁编造或复用 id"——模板示例的 `id:""` 此前会让 AI 把所有事件 id 都填空。

## 2026-09-06 — v1.5 修复"事件只新增不推进"(清单换血)

- **根因**: 提示词把事件清单表述为"整体替换", 思考流程只教"怎么新增"没有"先原样带回旧事件"的机械步骤——AI 每轮把清单整体重写, 同一件事换着标题反复出现/消失, 演变与前情全部断档; 输出模板的 id 示例为空串也让 id 对账第一步就失效(AI 甚至自编 EV-20250316-001 格式被守卫拒收)。

- **代码守卫·清单换血捞回**: `validateAndNormalize` 检测未认领旧事件占多数时, 把**未结束**(酝酿/进行/尾声)的旧事件自动原样捞回——AI 无权让进行中的事凭空消失; 真正"删除已结束事件"的意图不受影响; ≥50% 换血时 console 告警。
- **代码守卫·迫近纠偏**: 小事与已结束事件的"迫近/爆发"一律清回"无"——防止市井琐事被标"爆发"后经闯入机制强制注入主 AI(实测发生过"投喂活动标爆发")。
- **小小结兜底**: AI 偶发把「小结」写成「小小结」, 面板小结此前为空——`parsed['小结'] ?? parsed['小小结']` 兜底。

## 2026-09-02 — v1.2 事件因果链: 前情 + 演变

- **问题**: 事件是纯快照——每次推进整体替换清单、描述只写最新状态, 于是"数据"这类关键对象的来源随旧描述被覆盖 (悬空指代), 事件只看得到结果 4 看不到 2+2 (推导过程无留档), 注入给主 AI 的也只有最新状态、主 AI 同样不知道来龙去脉;
- **前情 (滚动总结)**: 事件新增 `前情` 字段——这件事的来龙去脉总结 (含起因), 世界引擎在推进时把本次变化**折进上一次前情**滚动更新 (旧前情随世界状态喂回, 不断链); 新事件创建时写定起因; 脚本端 AI 没给时沿用旧值兜底, 上限 200 字;
- **演变 (逐步流水)**: 事件新增 `演变` 时间线——世界引擎每次只报「变化」一句话 (有实质变化才填, 新事件必填), 脚本按标题匹配追加 `{世界时间, 变化}` 并去重, **历史由脚本持有, 清单整体替换吞不掉**, 保留最近 8 条;
- **注入**: 所有进行中事件 (含幕后/隐秘区块) 的注入行在描述后附独立一句 `前情: …` (不塞进括号尾巴, 渠道/关联保持原样式), 主 AI 能衔接每件事的因果; 已结束事件不带;
- **面板**: 风闻页事件描述下新增前情一行; 有流水时显示「演变·N」可展开时间线 (从早到晚); 修笔表单可编辑前情;
- **事件 id 对账**: 事件新增脚本签发的 `id` 字段 (AI 对既有事件原样带回、新事件留空, 严禁编造/复用)——对账先按 id 再按标题兜底, 一条旧事件只能被认领一次; **AI 改事件标题 (如"推进"→"延迟"、"X"→"X落幕") 不再丢失演变与前情**, 修复了"了结的事件从面板消失"——改名的已结束事件不再被反幻觉规则误判为凭空新事件而丢弃;
- **对账防滥用加固**: id 由脚本独占签发, AI 编造/复用的 id 一律不入档 (未认领到旧事件即重签); id 被顶/占用时继续尝试标题兜底; 同 id 同标题的复读条目去重; "无变化/暂无/同上"类占位词不追加进演变、不覆盖前情; 面板列表与演变展开状态改用 id 作 key (改名/重排不再丢 UI 状态);
- **头部填充对齐彼方**: 填充文本改为作为**第一条消息**单独发送(原为缝在 user 消息开头、排在 system 之后)——开启后 AI 收到的第一条就是填充内容, 消息结构与彼方一致(填充(user) → system → user 正文 → 破限时: system(SPECIAL NOTE) + assistant 承诺, v1.4 起破限段在任务后)。
- **提示词**: 描述禁止悬空指代 (关键对象交代是什么、从哪来); 标题要求稳定 (确需更名必须保住 id); 已结束事件默认保留仅明显过时才删; 字段文档/JSON 示例/推进指令/静默思考流程同步; 旧快照自动迁移 (前情空、演变为空、id 空——id 在下一次推进认领或新建时自动补齐)。

## 2026-08-31 — v1.1 事件知晓与隐秘机制

- **知晓台账**: 事件新增 `知晓` 字段 (未知/风闻/知情), 主角专属、烟火单写——新事件通常"未知" (主角所在地+本埠可直接"风闻"), 正文里听说/亲历升"知情", 传播=区域/天下 的进行中事件随时间被动升"风闻", 知晓只升不降; 旧快照缺省按"风闻"迁移;
- **隐秘事件**: 事件新增 `隐秘` 字段 (公开/隐秘); 生成侧"第三关·公共可见"改为"第三关·公开传播"——非公开的组织层暗中行动 (密谋/封锁/密报) 以隐秘事件入账, 不再被直接删除; 隐秘事件可曝光 (事败/走漏/见报) 翻转为"公开", 知晓给"风闻"; 旧快照缺省按"公开"迁移;
- **注入区块化**: 世界动向按主角知晓分区块——「主角已知的事」(可自然提及别重播) / 「幕后动向」(严禁未卜先知) / 「隐秘事件」(仅当设置开启, 标注"主角绝不可能知道") / 迫近警告; 迫近措辞按知晓自适应 (毫无察觉/已有风闻/已知悉), 隐秘的迫近事件豁免开关始终注入 (闯入需要主 AI 知情);
- **面板**: 风闻页事件行新增 隐秘 徽标与 知晓 元信息, 事件编辑表单支持修改知晓/隐秘; 上帝视角不变;
- **设置**: 运转新增「注入隐秘事件到主AI」开关 (默认关);
- **移除上限**: 删除「注入字数上限」「世界书内容上限」「世界书条数上限」——注入文本与世界书读取完全不截断; 头部填充文本可自定义 (留空用内置小说原文); 日志页长标题徽标改为小圆角并自动换行, 不再撑破面板。

## 2026-08-29 — v1.0 创建

- **世界推进引擎**: 每次 AI 回复后 (频率可配) 用独立 API 推进世界——时间流逝、事件因果演化 (新增≤2件/允许无事)、势力动向; 时间跳跃 (几天后/数月后) 大步推进并按跨度生成相应密度的事件;
- **第一定律**: 世界不围着主角转——事件只带"传播/渠道"等世界自身属性, 无主角知晓台账, 禁止为主角编织巧合与钩子;
- **事件模型**: 标题/描述/地点/时间/规模(小事·要事·大事)/传播(本埠·区域·天下)/渠道/势力/阶段(酝酿·进行·尾声·已结束)/迫近(无·关注·迫近·爆发); 清单整体替换、按时间排序、容量上限自动裁剪;
- **势力模型**: 目标/动向/对主角态度/最近变化, 从世界书与剧情自动识别, 至多 8 个;
- **世界书读取**: 与主 AI 相同的激活机制 (含 ACU `<if cell:>` 求值、EJS、宏替换、助手变量宏展开), 全局世界书开关 (默认关), 条目排除清单, 烟火自身条目自动排除;
- **尺度分工**: 只记世界尺度的大事件 (势力/群体/地区/天时), 人物层面的日常归彼方, 不读取彼方数据;
- **注入**: 「【烟火】世界动向」蓝灯常驻条目 (防递归), 精炼格式 + 防全知指导 + 迫近警告 (闯入力度可配), 切聊天自动重写;
- **楼层快照**: 状态整体存楼层变量, 删楼/重roll/切分支/编辑自动回退与作废, 保留最近 10 份; 清空世界走「清空层」机制;
- **面板**: 46px 墨印悬浮球 (拖动记忆) + 可拖动小窗面板 (点外部不关闭), 左侧竖排文字栏「此刻/风闻/脉络/日志/设置」, 黛墨×青瓷×朱砂配色, 暗夜/白天双主题;
- **设置**: OpenAI 兼容接口 + 命名预设 + 模型列表/测试连接 + 运转参数 + 标签过滤; 设置存全局变量, 导出脚本不带密钥;
- **Debug**: 日志页全量请求/输出/报错 + 注入预览 + 控制台捕获 + 一键复制报错报告; 解析失败自动重试 (3 次, 原样重发)。
