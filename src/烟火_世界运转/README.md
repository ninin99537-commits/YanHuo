# 烟火 · 世界运转系统 (Yanhuo)

每次更新项目同步更新此说明

一个运行在酒馆助手 (Tavern Helper) 中的脚本项目。与《彼方》互补且尺度分工明确: **彼方记录"小事件"——具体 NPC 的个人生活与行踪; 烟火只记"大事件"——组织、群体、地区、天时与远方变化**。主角看不见的地方, 时间照常流逝、各方按自己的盘算行动——世界不围着主角转, 主角只是世界里的普通一员。玩家通过面板以上帝视角看世界自转, 角色（主角）则只通过"传闻/告示/口信"等渠道自然听说这个世界。

## 工作原理

每次 AI 完成正文回复后 (频率可配), 用独立的 OpenAI 兼容 API 请求世界引擎。消息结构 (v1.4 起, 与彼方同款):

```
(头部填充开) user: 填充文本/内置小说原文     ← AI 收到的第一条
system: 核心提示词 (+防截断免责段)
user:   任务 (世界状态/最近剧情/正文/世界书)
(破限开) system: SPECIAL NOTE 身份强化       ← 任务后贴脸
(破限开) assistant: 承诺                    ← 看过任务后的应答
(预填充开) assistant: '{'                   ← 连续 assistant, JSON 起手
```

每次 AI 完成正文回复后 (频率可配):

```
正文生成完成 (防抖 800ms, 连发只推最后一条)
      ↓
烟火推进世界 (使用独立的 OpenAI 兼容 API)
      ↓
推进世界时间 / 事件因果演化 / 组织动向 (允许"无事发生")
      ↓
世界状态整体写入本次分析的楼层 (快照随楼层存亡)
      ↓
世界动向写入角色卡主世界书常驻条目, 主AI每回合都能读到
```

### 正文时间守卫

烟火的世界时钟以**最新一层正文**为唯一时间依据, 不会因为世界书里的未来日期或“世界自转”自行跳日:

- 正文写出明确的年月日时, 世界时间的日期必须与正文最新日期一致; 正文明确跨越数小时、数天或数月时, 允许直接跟随新日期。
- 正文只写“次日”“两周后”“几个月后”等相对跳跃时, 脚本按词义换算成允许的日期范围, 超出范围的模型结果会触发原有重试。
- 正文没有时间线索时, 世界时间日期必须沿用上一轮, 不允许凭空跨日; 时分等细节仍可由模型按剧情补全。
- 校验规则同时写入提示词与代码, 调试日志会记录本轮的“正文时间约束”, 便于确认一次推进为何被接受或拒绝。

因此, 一层正文确实经过几小时、几天、几个月并不会被代码拦截; 只有世界时间的跳跃没有正文依据, 或超出了正文明确给出的日期/范围, 才会被拦下。推荐把自动推进频率设为每 1~3 条 AI 回复, 让正文时间线索与世界快照保持足够近的上下文。

**口径补充(v2.8.5 D3)**: 世界时钟的解析入口只有 `时间校验.ts` 的 `解析日期` 一个,**中文年月日(`2008年5月2日 08:15` / `2008年5月2号`)与 ISO(`2008-05-02 08:15`)都吃** —— 引擎实际写出来的多是中文年月日, 所以"世界时间只存年月日、跨日就判不出来"这个担心在烟火里不成立; 这条路由 `tests/yanhuo-time-guard.test.ts [8]` 钉住。古代写法(`元和三年·三月初七`)仍按"不可解析"降级, 只提示不拦。

### 事件.组织 允许为空(v2.8.5 D6)

- **三段口径(v2.8.5 D6 的第二版, 块十五裁决)**: ① 清单里有这条线 → 填清单里那一条的名字; ② **题面/正文点了名、清单里却没有 → 也填那个名字, 即使它不在清单里**(真机原样: 这张卡写了「汉默工业在华盛顿召开特别吹风会」, 而清单里只有斯塔克工业董事会与神盾局 —— 那一栏就填"汉默工业"); ③ 真没有单一组织主体(自然/形势/跨组织的公共后果, 如"全球油价跳水""跨洋海啸")才留空。
- 为什么第②段是"也填"而不是"留空": **面板上出现一个清单外的名字是看得见、可解释的**(筛选时会出现这种孤儿值, 属预期), 而"描述里点了名、字段却空着"是隐形、事后查不出来的。
- **其余情况一律要填**: 留空 = 这件事在面板上按组织筛不到、那条线也收不到后果。
- **不做 schema 硬拦**: 组织清单为空的卡(开局/古代)会被硬拦逼着编一个组织出来, 代价更大; 校验层照旧把缺省值规范化成 `''`(`世界数据.ts`)。消费端: 面板按 `event.组织 === 选中组织` 筛事件(**可能出现清单外的名字**, 这是上面第②段的预期结果), 注入列里空值显示 `—`。

### 第一定律: 世界纯自转, 不围着主角转

- 每回合素材优先从五层常驻档案里长出来——**地区 / 形势 / 暗线 / 日程 / 指标**——不依赖正文; 正文只用于推时间、更新主角所在地区、以及可选的世界级涟漪;
- 硬规则: 事件清单里大多数事件的当事人和地点都不在正文里; 禁止为主角编织巧合、钩子、机缘, 禁止让事件刻意针对或为难主角;
- **事件合格线**(三问全过才算): 集体/组织/制度/公共层面的动作或后果; 会被跨地区的人当作议题/情报; 对格局或某方处境有可累积的后果。天气/基础设施故障/市井日常/个人起居一律不入账;
- 组织暗中行动走**保密事件** (`公开性`: 公开/保密): 不走公共渠道, 默认只进面板不注入主 AI (可开关注入并标注"主角绝不可能知道"); 保密可曝光 (事败/走漏/见报) 翻转为公开;
- 主角是否听说某件事, 由主 AI 按常识与剧情把握, 引擎不再维护主角知晓台账。

- 升级后旧版脚本读不懂新存档, 回退版本前先备份聊天。

### 面板 (v2.9.7 「简报」)

悬浮球 (40px 圆, 一簇灯火; 可拖动, 位置记忆) 点击弹出浮动面板 (窄而高, 约 400×660; 可拖动顶栏, 点外部不关闭, 仅收起按钮或再点悬浮球可收起)。球上右上角的小数字是进行中的事件件数; 推进中球的边线里转一段弧。

- **抬头**: 世界时间是整块面板最大的字(末尾是"时:分"时放大时分、日期放小字), 下面是主角所在。推进中顶栏状态变成推进文案 + 「中断」, 时间下面一根细线在走。
- **简报** (一页从上读到下, 顶上那排按钮跳到对应一段):
  | 段 | 内容 |
  | ---- | ---- |
  | **此刻** | 氛围/总览/节奏、推进/暂停自动/编辑(改时间/主角所在/氛围/总览)/清空(点两次)、推进次数与小结 |
  | **所在地 · 近期日程 · 数据变化** | 有才出; 挑选规则与注入给主 AI 的【所在地】【近期日程】【数据变化】是同一份(公开摘要.ts 的 取近期日程 / 取数据变化) |
  | **动态** | 事件纪事流 (最新在前), 按阶段/规模筛选; 每条: 时间·地点·传播·渠道 / 标题(重大事件带红色小方印) / 描述 / 背景 / 重大·阶段·保密·到期判定·组织·人物标签 / 可展开的演变; 悬停出现编辑与移除 |
  | **组织** | 组织名一排, 点哪个看哪个: 目标/负责人/动向/覆盖范围/外部关系/关联事件, 可编辑 |
  | **世界** | 形势/地区/暗线/日程/指标五层档案, 可增删改 |
- **日志** (右上角图标): 最近一次推进的完整请求/输出/报错 (可展开可复制)、每次尝试、注入给主AI的内容预览、控制台输出、一键「复制报错发给助手」。
- **设置** (右上角图标): 接口配置 + 命名预设、请求技巧、运转、注入主AI、世界书与标签; 最下面一行是模型 · 快照楼层 · 版本。
- **提示条与推进弹条**: 仍贴在球旁边(左侧优先, 放不下到右侧; 被收纳坞收走时贴坞图标), 面板开着时先压住、关面板后按顺序补发。外观跟面板同一套: 左边一条色带(成功=钴蓝, 错误=红并整块换红底, 普通=灰, 警告=正文色), 不再晃动; 推进弹条是"转圈 · 文案 · 计时 · 中断"。

配色 / 字体 / 球径 / 层序只在 `主题.ts` 一处(钴蓝是唯一的强调色, 红只给重大事件、错误、危险操作); 样式表里一律 `var(...)`。面板里不写按宽度的媒体查询 —— iframe 的视口就是"球 ∪ 面板"那块矩形, 桌面上也会命中。

### 世界书与 AM 记忆: 独立重扫，不冒充同一批输入

烟火会按所选聊天材料独立执行世界书激活求值（蓝灯常驻、绿灯关键词），保留每个命中条目的完整文本与书名/uid/AM 键等来源信息。条目里的 ACU 模板 (`<if cell:...>`)、EJS 模板、酒馆宏会先求值。默认只读角色卡主+附加世界书与聊天世界书; **全局世界书有开关** (默认关); 支持按条目名/关键词排除, 烟火与彼方自己写入的条目自动排除。

**相同激活算法不代表同一批请求输入。** 记忆插件在最终发送前挑选 AM 并追加 `<recall>` 激活码；烟火另行扫描自己的完整原文，未核实主请求最终实际激活集合，因此不会声称“主 AI 与烟火读到同一批记忆”。AM 条目作为只读剧情历史单独提供，不与事实设定混写。

- `AM0256 | 0m` 等编码与 now/today/years 分组只是检索来源和相对年龄，**不代表这些行为本轮再次发生，也不是世界时钟前进的依据**。
- 记忆缺失不等于事情没发生，近期未提不等于事态解除；旧记忆不能推翻较新的明确结果。
- 激活码属于只读来源元数据，不是要求生成的叙事内容。未闭合的 `<recall>` 不取半截使用：该轮保留完整原文并拒绝推进。
- 预期 AM 码只用于完整性审计和告警；读不到时不伪造映射、不补写不存在的记忆。
- 完整楼层、正文、AM 条目与错误原文都**绝不按字符/token 从中间截断**。本轮输入过多时只选择完整条目；必要内容超出字符目标会完整保留并提醒，字符数不冒充 token 计数。

### 与彼方的分工

彼方管"人"(NPC 个人生活, 小事件), 烟火管"世界"(组织/地区/远方, 大事件), 两边各记各的、互不重复:

- 烟火推进时**不读取彼方数据**、也不生成人物层面的日常事件——人物归彼方, 世界归烟火;
- 读世界书与主 AI 完全一致: 彼方写入的 NPC 条目也照常读取(它们就是世界的一部分), 但提示词不提彼方, NPC 状态只作背景、不作事件素材;
- 主 AI 两份都读: 彼方的 NPC 状态 + 烟火的世界动向, 由主 AI 在剧情里自然融合。两插件彻底解耦, 彼方未安装时烟火照常运转。

## 配置

### 接口

- **独立接口**: 任何 OpenAI 兼容服务 (地址末尾自动补 `/v1`), 「获取模型列表」拉取后下拉选择, 「测试连接」发一条短消息验证;
- **命名预设**: 可保存多套接口配置 (地址/密钥/模型/参数整体保存), 一键加载切换, 不用重复填写;
- **流式 / 预填充 / 温度 / 最大输出Token**: 对接不同模型的兼容选项。

### 运转

- **自动推进 + 更新频率**: 每次或每 N 条 AI 回复推进一次; 正文过短 (疑似截断) 自动跳过;
- **注入世界动向到主AI**: 写入角色卡主世界书常驻条目「【烟火】世界动向」(蓝灯常开、禁递归), 切换聊天自动重写当前聊天的内容, 关闭或世界为空时删除条目; **目标仍是角色卡主世界书，不自动创建/重绑聊天世界书**。公开摘要只选择完整的公开事件及明确公开结果，不透传可能复写秘密的自由总览/组织暗流/形势走向；默认正常档最多4件完整事件，未选中的记录仍在存档(这一点只对你说, 注入文本里不写)。超字符目标只提示，不裁剪。
  - **注入什么(v2.9.0)**: 每条事件只写 `时间 / 地点 / 当前 / 背景 / 渠道 / 归属 / 代表人物`(字段与顺序来自 `世界字段表.ts` 事件层的 `注入列`)。**不写等待条件**(引擎调度用), 也不写"另有 N 条…仍在存档里"之类的账本话术。
  - **背景**: 只给主角所在地的事件; 主角所在未知时全部保留, 信息量与 v2.8.x 相同。
  - **主角所在(v2.9.1)**: 世界引擎每轮按最新正文填 `世界.主角所在`, 脚本按固定次序核对 —— 正好是地区名 → 与地区名互相包含(取最长) → 对不上就照用(可能在地区档案之外) → 没给就沿用上次 → 上次也没有才去最新正文里找最后出现的地区名。注入抬头写成 `世界时间：… ｜ 主角所在：…`。面板抬头显示这一项, 编辑里可以改。
  - **当地看得见的三段(v2.9.1)**, 各自有条件, 不满足就整段不出:
    - 【所在地】主角所在正好是某个地区名时: 概况 / 局势 / 主事方 / 外部关系(不带背景; 外部关系 v2.9.4 起带上, 提示词没对它加"只写看得见的"约束);
    - 【近期日程】日程层开着、0~7 世界日内会到、周期不是每天, 最多 3 条, 写成"N天后/明天/今天"; 日期解析不了(古代历法)的不注入, 不伪造;
    - 【数据变化】指标层开着、趋势不是平稳, 最多 3 条。
    - 日程与指标的**范围**(v2.9.5): 可选字段, 填所属地区名, 空 = 全境。注入时全境的总是给, 有范围的只在与主角所在对得上时给; 主角所在未知时不过滤, 但在括号里标出范围(免得主 AI 当成本地的)。面板的日程/指标编辑表单里能改。
    事件与已结束结果放在【动态】下。提示词另加一句: 地区局势只写当地人看得见的状况, 暗中动作记成保密事件 —— 因为局势现在会进【所在地】。
  - **传播时滞(v2.9.2)**: 远方的公开事件按"传讯速度"晚几日才进注入。设置 →「注入主AI」里有**传播时滞**开关(默认开)和**传讯速度（本聊天）**下拉。传讯速度**不设默认**: 每个聊天单独选(存在聊天变量里, 删楼/重 roll 不回退, 清空世界也保留), 没选就不生效。
    - 地缘: 本地 / 邻近(两地任一方的「外部关系」提到对方; 事件没写地点、主角所在不在地区档案里、或所在地外部关系为空时放宽为邻近) / 远方。
    - 时滞(世界日): 古代 全域 7 · 区域 4; 近代 2 · 1; 现代 0 · 0。本地恒 0; **传播为本地的事传不出当地, 区域的事到不了远方**(现代也一样); 规模为重大时传播升一级。
    - 听到哪一步: 在事件的演变里取「这一步的时间 + 时滞 ≤ 现在」最晚的一步。传到的就是最新 → 照常注入, 标题带 `本地见闻/外地传来 · 公告/传言`; 只传到较早一步 → 写成 `（外地传来 · 约N天前的消息 · 传言）` + `当地所闻：那一步的变化`, **不写远方此刻的"当前"与背景**。一步都没到 → 本轮不注入。
    - 远方已经了结、结局还没传到的事, 仍按最后听到的那一步当传闻注入(不会凭空消失); 结局传到后才进"已结束事态…的公开结果"。
    - 公告/传言: 渠道含 告示/榜文/布告/公告/邸报/官报/通报/公文/报道/新闻/快讯/通告 为公告, 但跨地且时滞 > 0 时一律降为传言(辗转了)。脚本不改写内容, 只用一句话提醒主 AI"传言可能走样"。
    - 保密事件不走公共渠道, 不按传播过滤(仍只在「注入保密事件」开着时进)。
    - 不生效(传讯速度未选 / 主角所在未知 / 世界时间解析不成公历)时注入与 v2.9.1 逐字一致, 推进记录的备注里写一句原因。纯脚本推算, 不调模型、不改世界状态、不改请求体。
  - **节奏事实(v2.9.3)**: 请求里在【运转密度】下一行加一句 `【节奏事实】截至上次推进的世界时间，距上次重大事件：约N世界日；距上次新增公共事态：约M世界日。这只是事实，不是额度，也不要求本次必须生事。`(也可能是"当日 / 尚无记录 / 无法换算"; 首次建档整行不出)。两个时间记在 `统计.上次重大事件时间 / 上次新增时间`, 提交时由脚本维护 —— 有新增就更新新增时间; 有重大事件新出现或换阶段(含结束)、或有暗线变成已发生就更新重大事件时间。旧快照没有时按 事件 + 已结束 反推。**不是配额**, 零新增仍然合法。
  - **到期掷骰(v2.9.3)**: 设置 →「运转」里有**到期掷骰**开关(默认开)。事件到了「下次判定时间」(按基准世界时间 + 本轮至少跨过的世界日算), 推进前由脚本用浏览器真随机掷出 推进 / 僵持 / 受挫:
    - 权重: 常规 40 / 35 / 25; **重大 30 / 45 / 25**(牵扯方多, 更容易卡住)。
    - 掷出的事件**强制进工作集**(优先级高于正文提及), 请求里那条事件附只读的 `"到期判定":"推进"`; 提示词有一条约束说明三种结果怎么写、与已叙述的正文冲突时以正文为准。
    - 同一轮的三次原样重试发的是同一份请求, 结果一致。
    - 提交时: 模型展开了这一步(演变多了一步 / 阶段变了 / 已结束)就清掉; **没展开就把判定写进事件, 下一轮沿用同一结果, 不重掷**, 推进记录备注里记一句; 到期点被改掉的旧判定清掉。
    - 分支: 判定只随提交的快照落盘。重 roll / 新 swipe 从上一层快照重新推进, 本轮新掷的会重掷; 上一层已经落盘、还没展开的沿用。
    - 判定是脚本独占字段(和 id、演变一样), 不进事件 JSON 示例、不进注入。面板手动修改事件会丢掉它, 下次到期重掷。
  - **挑哪几条(v2.9.0)**: 按确定性分数整条挑, 不看数组位置 —— 本地 +30、重大 +15、全域 +10 / 区域 +5、进行中 +5 / 收尾 −5、最近进展 ≤3 日 +10 / ≤10 日 +5、上次注入过 +8; 同分按最近进展新者在前, 再按事件键。"上次注入过"由推进提交时记进快照(`上次注入`), 删楼回退跟着回退; 这一项让同一件事不会这轮出现、下轮消失(主 AI 会误以为它结束了)。
  - **已结束结果**: 只注入 30 世界日内结束的最近 N 条; 时间不可解析(古代历法)时退回"最近 N 条"。
  - 不按"正文提及"加分: 切聊天、面板预览时也要重算注入, 那时手上没有正文, 加了会让同一份数据注出两种结果。
- **本轮推演工作集**: 默认正常档最多6件完整旧事件，优先正文提及、已到期与进行中的事，并轮换未重点跟进记录。其余完整事件不发给本轮模型，也不修改、不结束;
- **模型输出协议**: 固定 `烟火增量-v2`（v1 照收，老键名搬到新名下），只返回新增/变化的完整条目；缺协议时不按内容形似猜测。省略的旧记录由脚本完整保留；模型校验、快照提交、世界书同步分别报告，世界书失败不会把已保存快照说成整体失败;
- **保密事件**: 默认关闭——保密事件只进面板; 开启后以"保密背景（主角不得无依据知晓）"的标注注入, 帮主 AI 写好暗中戏;
- **日程 / 世界指标**: 两个可选层开关, 关掉即不生成、不维护该层;
- **运转密度**: 稀疏 / 正常 / 密集, 默认正常——普通新增上限为1/1/2件，有正文依据的跨日上限为1/2/3件，进行中准入参考为8/10/14条，重点跟进为3/6/10条，公开摘要为2/4/6条。**这些是上限而非生产目标，零新增始终合法；旧档超额完整保留，不强迫收尾或删除。** 可选逐档覆盖额度，只按整条选择，绝不裁字段正文。
- **读取最近回复数 / 读取世界书 / 包含全局世界书 / 世界书排除** (世界书无条数与字数上限——主 AI 激活多少就读多少);
- **头部填充文本**: 可自定义的填充文本, 开启「头部填充」后作为**第一条消息**单独发送(与彼方同款), 留空使用内置小说原文;
- **楼层标签过滤**: 排除/只读 指定标签 (如 `thinking`、`aftertalk`), 兼容带属性写法, 始终清理 HTML 注释与 Subtext 思维链整块。

## 楼层快照: 删除楼层 = 世界自动回退

世界状态整体存在**楼层变量** (键 `烟火`) 里, 每次推进写入本次分析的最后一条楼层:

- **删除楼层**: 快照随楼层消亡, 世界自动回到更早楼层的快照 (保留最近 N 份, 份数可在设置「快照保留份数」调整, 1~100 默认 10; 写入新快照时物理清理超额);
- **回退窗口耗尽**: 连续删楼/编辑把全部快照锚点作废后, 世界会归零 (等同新开局)——想删更多楼还保住世界, 就调大保留份数; 注意每份快照几KB~30KB, 调得越大聊天文件越胖;
- **重roll/regenerate**: 新 swipe 页没有快照, 自动回到上一层状态, 随后正常推进;
- **编辑/滑动楼层**: 提交时核对聊天、swipe、完整正文、世界修订和清空世代；变化后晚到的旧响应不得覆盖当前快照或主世界书。正常流式收尾/正则后处理不再用旧 hash 规则误删快照;
- **切回旧 swipe 分支页**: 恢复该页当时的快照;
- **重推**: 非破坏性读取更早基准；新响应未通过校验前不撤销最后一份好快照;
- **清空世界**: 持久记录「清空截止」与清空世代，不在第一次推进后消费；之后只推进比它更新的完整楼层，旧分支不能复活已清空内容;
- **归档只存一份**(v2.9.6): 已结束事件、失效暗线、过期日程的内容放在聊天变量 `烟火_归档` 里(按内容指纹去重), 每份楼层快照只记引用清单 —— 删楼回退时"哪些算已结束"仍由那份快照的引用决定。池子只增不删(被回退掉的归档会留下少量孤儿), 清空世界时整池删除。旧快照里内嵌的归档照常读; 引用在池里找不到时略过那一条并在控制台报一句。索引写成功后, 快照里为失败回退准备的「前一快照」随即清掉;
- **完整历史**: 每条事件的全部演变、已结束事件、失效暗线和过期日程均按完整记录保留。公开摘要/本轮工作集的整条选择不是删除；控制成本不靠截断历史。

聊天变量 (键 `烟火`) 只存轻量索引 (快照楼层列表 + 清空层), 归档池另放在键 `烟火_归档`。**每个聊天都是独立的世界**——切换聊天/角色卡互不干扰, 新聊天从零建档。

### ⚠️ 为什么不能直接 `git push`

工作区的 `git remote -v` **只有一个 `origin`，而它恰好就指向 YanHuo**——看着像"推 origin 就发布了"，**但并不是**：

1. **投影仓不是工作区的镜像。** 工作区 `src/` 下有 8 个插件，YanHuo 只装 2 个（烟火 + 共用）。直接推会把剧情导演 / 正文美化 / 直播弹幕 / 自定义状态栏一并带过去。
2. **两者历史已经分叉。** 工作区与 `origin/master` 各有独有提交（实测 `git rev-list --left-right --count HEAD...origin/master` = `223 20`），普通 push 会被拒。
3. **`dist/` 的跟踪状态相反。** 工作区 `.gitignore` 里写着 `dist`（不跟踪），而两个投影仓都**跟踪** `dist/`——用户粘贴的就是仓里那份。

所以发布 = **投影**：把文件复制到目标仓的检出里，在那里重新提交、再推。**不是** push 工作区。


### 陷阱清单

- **① 提示词里不许出现我们自己的验收语言(2026-10-11 收口)。** `prompts.ts` 里**会进请求体**的文字只允许两类：① 对世界引擎的指令；② 世界内的例子（就是世界里的句子本身）。**禁止**：真机 / 实测 / 线上 / 第N轮 / R1 / 转述 / 存档 / 用例 / 断言 / 白名单 / fixture / B栏 / 臂 / A′ / 验收 / 探针 / 这张卡 / 清单外 —— 以及 `面板`（它也是我们的词，不是世界里的词：v2.8.5 收口时正是它在请求体里漏网）。**不受限**："逐字原样带回 / 原样带回"这类**指令性**用法（那是给模型的照抄要求，不是溯源标签，删了就等于废掉增量维护规则），以及 `//` 与 `/** */` 注释里的任何话。理由：世界引擎不知道也不该知道"真机""第三轮"是什么；混进去既是噪声，又会被模型当设定去理解。护栏：`yanhuo-prompt-freeze [0]` 里那条通用断言 —— **只扫成品 `SYSTEM_PROMPT`（我们自己拼的那份文本），不许扫整份请求体**：请求体里还有用户卡的世界书与正文，那里出现"真机/面板/第N轮"是**完全正常**的（那 60 余处"威胁"就全在世界书里），扫全量必**误红**。命中哪几个词就把哪几个列出来。
- **② 同一个测试文件不许两个方向并发编辑。** 共享用例文件（尤其 `tests/yanhuo-prompt-freeze.test.ts` 这种带白名单与段号的大文件）一律**串行**：一方在改白名单、另一方同时在加断言，就是 2026-10-11 那次"抹掉 22 条新增 + `[3]`/`[4]` 两段"的根因。配套硬规矩：**禁用跨行替换**（找起点再找下一个引号/花括号 —— 引号与花括号会落在字符串里，正则静默吃错区间），一律按整行定位。动手前先看一眼 `LastWriteTime`，别在别人刚写过之后盲落笔。真出事了的救援顺序：`git show HEAD:<path>` 拿回底稿 → 从最近一次 `tests/.build/*.mjs` 里捞数据（esbuild 把字面量原样编进产物，只是非 ASCII 转义成 `\uXXXX`，解码后 `eval` 就能取回）→ 修完必须让用例自己那两条"集合恰好等于"的断言转绿（它是重建正确与否的判据）。
- **`dist` 必须一起带上。** 工作区不跟踪它、投影仓跟踪它。漏了会让线上产物停在旧版（`[bot] bundle` 能兜底重建，但中间态期间线上是旧的）。
- **暂存闸门用"投影仓已有文件"规则，不再维护手写白名单（2026-10-11 裁决）。** 手写白名单会被版本演进打穿：v2.8.5 要同步的 `src/共用/模型往返.ts` / `webpack.config.ts` / `global.d.ts` **早就在投影仓里**，却不在旧白名单里 → 整轮推不出去。新规则两条：① 暂存的每个路径必须**已存在于 `origin/master` 的树里**（唯一例外 `dist/烟火_世界运转/**`，由 CI 重建）；② 暂存清单**逐条打印**，落在本插件地盘（`src/烟火_世界运转/`、`tests/`）之外、又不在仓里的新路径**必须人工批准**才放行（`src/剧情导演/**`、`src/彼方_*/**`、`tmp/`、`.work/`、`_verify/`、以及根目录上任何非仓库文件都会被它拦住）。
- **版本注入要在投影仓里当场验一次。** 投影仓自己那份 `webpack.config.ts` 若没同步，CI 重建出来的 dist 里 `__构建信息__` 会退化成 `unknown`。判据别写错：源码是模板串，产物里是 `"[烟火] 世界运转系统已加载 "+Ht()`，所以**不能查整串**"世界运转系统已加载 v"（一份完全正确的产物也会判 False）；要分开断言"启动串 + `v2.8.5`"，并从产物里取出**注入的那一份** commit 字面量（形如 `{commit:'9cd3107',…}`）判断它是不是真提交号 —— 兜底的 `{commit:'dev',…}` 是永远在产物里的，不能拿"产物里有没有 dev/unknown"当判据。
- **CI 支路已实测（浅克隆 + 两个分支）**：`--depth 1` 检出下，`GITHUB_SHA` 存在时注入它的前 7 位；不设 `GITHUB_SHA` 时 `git rev-parse --short HEAD` 在浅克隆里照样拿得到真提交号（实测 `4313595`）——**都不会退化成 `unknown`**。推完仍要复核一次仓里的产物（`dist` 由 bot 重建）。
- **别把其他插件带过去。** 剧情导演 / 正文美化 / 直播弹幕 / 自定义状态栏不属于这个投影。
- **`.github/workflows/` 只放 `bundle.yaml`。** 模板上游另有 `bump_deps.yaml` / `sync_template.yaml`，那是模板仓维护用的，两个投影仓都没有它们（本工作区也没有 `.github/workflows/`，这几份文件只在模板仓与投影仓里）。
- **投影仓要各自装一次 `jsdom`（测试专用依赖）。** `tests/提示条.test.ts` 用 jsdom 把酒馆父页面摆出来，第一次真跑提示条的 DOM（以前只能断言源码文本，因为它画在 `window.parent.document` 上）。工作区这边已加进 `devDependencies`，但**投影仓的 `package.json` / 锁文件不在同步清单里**（它们各活各的），所以进仓后要 `pnpm add -D jsdom`；漏了会让 `pnpm test` 在打包那一步就红。
- **`tests/platform-usage.mjs` 已兼容"缺项目"的投影仓。** 它扫的项目目录不存在就跳过（`statSync(..., { throwIfNoEntry: false })`），不再抛 `ENOENT`。所以投影仓里 `pnpm test` 最后那道「平台直连检查」不会因为它变红；**它红了就是真的出现了 `host.ts` 之外的平台直连**——那才是它要抓的东西。
- **新克隆没有 git identity：`commit` 会失败，而 `push` 会撒谎。** 投影检出是全新克隆，本地与全局都没配 `user.name` / `user.email` 时，`git commit` 直接 `exit 128`（`Author identity unknown`）；**紧接着的 `git push` 会报 `Everything up-to-date`** —— 看起来像推成功了，其实根本没产生提交（工作树还是脏的）。先设本地身份（`git -C <检出> config user.name "..."` 与 `user.email "..."`，**只写本地、别加 `--global`**）再提交。
- **判断推没推上去，看 `rev-parse` / `ls-remote`，不看 `push` 的输出。** `Everything up-to-date`、`Already up to date.` 都可能出现在"什么都没发生"的场景里。推完用 `git -C <检出> rev-parse HEAD` 与 `git -C <检出> ls-remote origin master` 对一次，两边一致、且 `status --porcelain` 为空，才算真的落地。
- **产物更新有延迟。** 投影仓的 `[bot] bundle` 会自动打版本 tag；推完要等它重建完，再在酒馆里重新粘贴一次产物才算更新到用户手上。

> 🤖 该仓库有 `[bot] bundle` 工作流：推源后机器人会自动 `rm -rf dist && pnpm install && pnpm build` 并补一个提交，所以即使偶尔漏提交 dist 也会被兜底重建；但它只重建**仓内存在 `index.ts` 的插件**，而产物由 `webpack.config.ts:54` 的 `globSync('{示例,src}/**/index.{ts,tsx,js,jsx}')` 决定。
> ⚠️ **本机构建与 CI 构建不可能逐字节相同**——webpack 的模块 ID 由模块绝对路径派生，而两台机器的检出路径不同（实测同一段代码：本机 `777(e,n,t)`、CI `463(e,n,t)`）。所以推完源码后机器人**几乎总会**再补一个提交，这是正常现象，不是出错；也不必试图靠"提交一份完全一致的 dist"来避免它。
> 推送被拒（non-fast-forward）时，多半是机器人刚补过一行：`git rebase origin/master` 后再推。
