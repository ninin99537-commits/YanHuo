# 烟火 · 事件因果链（前情 + 演变）设计

日期: 2026-09-02
状态: 已批准（用户确认双轨方案 + 全部进行中事件注入前情）

## 问题

事件模型是纯快照式: 每次推进返回全量事件清单整体替换，描述只写"当前最新状态"。导致:

1. 悬空指代——事件描述里的关键对象（如"数据"）的来源留在上上次推进的旧描述里，被覆盖后无人能懂;
2. 因果链丢失——只看得到结果 4，看不到是 2+2 还是 8/2（推进的推导过程没有留档）;
3. 主AI同样不知情——注入只带最新状态，主AI也无法衔接事件来龙去脉。

## 方案（双轨）

每事件新增两个字段，同一次推进调用内由世界引擎维护，脚本端兜底累积:

- **前情** `string`: 这件事的来龙去脉总结（含起因），AI 滚动维护——每次推进把本次变化**折进上一次前情**（旧前情随【世界当前状态】喂回，机制上不断链）。上限 200 字。
- **演变** `{时间, 变化}[]`: 逐步流水。AI 每次只报「变化」一句话（有实质变化才填），脚本按标题匹配既有事件后追加 `{新世界时间, 变化}`（与上一条去重），保留最近 8 条。**历史由脚本持有，整体替换吞不掉**。

### 维护规则

- 新事件: 前情 = 起因（它是什么、从哪来）; 变化 = 它的出现（第一步轨迹）;
- 既有事件有实质变化: 变化 = 一句话; 前情 = 折叠更新版（非重写）;
- 无变化: 变化留空，脚本沿用旧前情与旧演变;
- AI 忘写前情: 沿用旧值，链条优雅降级（流水仍在）;
- 事件改名会断链（按标题匹配，与现有 diffEvents 同局限）——提示词要求标题稳定;
- 重roll/删楼回退: 演变随楼层快照自然回退，自洽。

### 呈现

- **主AI注入**: 所有进行中事件（含幕后/隐秘区块）行尾追加 `（前情: …）`; 已结束不带;
- **面板·风闻页**: 描述下新增前情一行; 有流水时显示「演变·N」可展开时间线（从早到晚）; 修笔表单可编辑前情、不可编辑演变;
- **提示词**: 描述禁止悬空指代; 字段文档、JSON 示例、推进指令、静默思考流程同步。

### 迁移

旧快照缺省 `前情=''`、`演变=[]`（面板隐藏空值），因果链从升级那拍开始积累。

## 改动面

schema.ts（类型）→ state.ts（EVENT_HISTORY_LIMIT=8、快照迁移）→ update.ts（normalizeEvent 解析 变化/前情 + 合并逻辑）→ prompts.ts（SYSTEM_PROMPT、输出示例、推进指令、formatEventLine）→ 悬浮球界面.vue（展示/编辑/样式）→ README.md（v1.2 更新日志）。

## 增补（实测后）: 事件 id 对账

实测发现 AI 会给事件改名（如"议程推进"→"议程延迟"），标题对账断链导致: ①改名事件的演变/前情整体丢失; ②改名后标记"已结束"的事件被反幻觉规则误判为凭空新事件而丢弃（面板上"了结的事件消失"）。增补:

- `WorldEvent.id`: 脚本签发的唯一标识（`e` + 时间36进制 + 随机尾）; AI 对既有事件原样带回、新事件留空，脚本为权威（认领到旧事件沿用其 id，冲突/篡改一律以旧为准）;
- 对账顺序: 先 id 后标题兜底; `usedOld` 集合保证一条旧事件只能被认领一次;
- "新事件不得直接已结束"的判定改为"对账不上任何既有事件"——靠 id 认领回的改名事件了结合法;
- 旧快照 id 为空: 下一次推进按标题认领时自动补齐。

### 二次加固（复查 AI 不可信边界）

- id 独占签发: 未认领到旧事件的事件一律脚本重签 id，AI 编造值（"1"、"event2"…）永不入档，杜绝重复 id 入库;
- 兜底链修正: id 命中但已被认领时继续尝试标题兜底（原实现 `byId || byTitle` 会被占用的 byId 短路）;
- 复读去重: 同 id 同标题的重复条目只保留第一份;
- 占位词过滤: "无变化/暂无/同上"类填法不追加演变、不覆盖旧前情;
- 面板 v-for key 与演变展开状态改用 id（改名/重排不丢 UI 状态）。
